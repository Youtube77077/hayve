# Hayve: notes for future development sessions

- Expo SDK 54 / React Native 0.81 / Expo Router 6, TypeScript. Routes live in `src/app/`. Use `npx expo install <pkg>` to add native deps. `.npmrc` sets `legacy-peer-deps` (needed for `@rnmapbox/maps` + `mapbox-gl` v3); keep `vite` as an explicit devDependency for vitest.
- UI must only talk to `src/backend/api/*`. Never import `store.ts` or `getDb()` from screens.
- Read data with `useLive(() => api.x.y())`; mutate with `const { run } = useAction(); run(() => api.x.z(), { success: '…' })`.
- Design: `src/design`. Colours ONLY indigo #4F46E5, black #0E0E10, white, greys #F4F4F6/#E5E6EA/#6B6E78. No gradients, no coloured tiles or icons, no tinted backgrounds. Lucide outline icons via `Icon` (indigo only for active/selected). Plus Jakarta Sans via `font()`. 8px grid, 12–16px radius. Logo/wordmarks: `src/design/logo.tsx`, `src/features/nav/Wordmarks.tsx` ("Hayve" always bold).
- Emoji: at most one per screen (home greeting, small confirmations) via `<Emoji>` (native on Apple, Fluent elsewhere).
- International, US first: never hard-code a country, city, currency or bank. Country → currency/bank rail/banks/IDs/tax in `src/backend/regions.ts`; format money with `money()` (UI) or `fmtMoney()` (backend), never a literal €/$. Ride places are quick picks per city (`places.ts`); Ride works anywhere.
- Money is integer cents through the ledger (`src/backend/ledger.ts`). Never store balances. Label simulated money with `<SimBadge />` ("Demo").
- Fees and Wave Back values live in `src/backend/config.ts` (admin overrides in `db.settings`). Buyers see one "Fees" line, never a percentage. Never say cashback/points/credits.
- Hayve Send exists only inside the Shop checkout and order page; not in nav or Home.
- Maps: always `HayveMap` from `src/features/map` (Mapbox with keys from env; Apple Maps + `modules/hayve-apple-maps` on iPhone without a key). See docs/MAPS.md.
- Motion: use `src/design/motion.tsx` (`Appear`, `usePressScale`, `useShake`, `SuccessMark`, `HeartButton`, `Tilt`, `useHotkey`); always respect reduced motion.
- Hayve Pay is an internal wallet only (see docs/PAYMENTS.md): balance, add money via provider checkout, spend across Hayve, balance+card for the rest, withdraw to a payout account, send, request links. No Tap to Pay, cards, bank connections or payment network: don't add them back. Requests/links: `src/backend/api/requests.ts` (splits: N people or "not sure", 72h, progress only for the requester). Ride dispatch (one driver at a time, 15% commission) in `api/ride.ts`; settings `payRequests`, `ride` in config.ts.
- Payment provider seam: `server/src/payments.ts` (Stripe checkout/webhooks); keys in env only.
- Logo: regenerate with `python3 scripts/build-logo.py && node scripts/render-logo.mjs assets`.
- Anonymous gifting privacy is a hard requirement; see docs/ARCHITECTURE.md. Keep tests green:
  - `npx vitest run` (app backend), `bash supabase/tests/run.sh` (PostgreSQL), `cd server && npx vitest run` (API)
- Before finishing: `npx tsc --noEmit && npx expo lint && npx vitest run && npx expo export --platform web`.
- Bump `DB_VERSION` in `src/backend/seed.ts` when the stored data shape changes (it reseeds local data).
- Owner admin: `rojyarzakholi@gmail.com` (config.ts and migration 0005). Admin needs verified email + 2FA; only admins add admins. Preview codes: `SIM_CODE` 246810.
- Hosting: DigitalOcean. Single droplet: `deploy/droplet/` (docker compose: Caddy + API + PostgreSQL; `setup.sh` one-liner, docs/DROPLET.md). App Platform alternative: `.do/app.yaml`, docs/HOSTING.md. The app still runs on the simulated backend.
- iOS: pushing to `main`/`claude/**` builds an unsigned IPA via `.github/workflows/ios-ipa.yml` and publishes a pre-release; `main` also refreshes the `ios-latest` release (permanent link: releases/latest/download/Hayve.ipa) with an AltStore/SideStore source (releases/latest/download/altstore.json) for automatic updates; each build is versioned 0.1.<run>.
- 1,000-person simulation (real backend, synthetic people): `npx vitest run --config sim/vitest.config.ts && node sim/report.mjs <outDir>` → HTML report + people.json. The sim adds its own example catalogue (`sim/catalog.ts`), never the app's seed. Re-run after big flow changes; it must report 0 crashes and a balanced ledger. Price analysis: `node sim/pricing-report.mjs <outDir>` (uses sim/out/pricing.json; the sim freezes the clock per step and models rush hours/events).
- Price records (`recordPrice`) must equal what the customer paid: add non-engine parts (delivery, cleaning, taxes, insurance) with `withExtras()` in `api/revenue.ts`; pass-through money is never Hayve revenue.
- Bites only lists/accepts restaurants in the customer's city (`bites.coverage()`, `metro()`); new restaurants need a `city`.

## Shared rules for all Hayve work (from the owner's prompt pack, docs/PROMPTS.md)
- Hayve is one app, one account, one balance: Pay, Shop, Rides, Eats, Stays, Rentals, plus partner apps (sellers, drivers, couriers, restaurants, hosts, rental owners).
- White interface, indigo accent, black text and black line icons. No coloured or tinted service tiles. Calm, lots of whitespace.
- Buyers see fees only as a "Fees" amount, never a percentage. Money back is real balance money, never "cashback".
- Before changing anything: read the code, then list what exists, what's broken and what you'll change. Refactor step by step; don't rewrite working features; keep the app running.
- Every new feature: loading, empty and error (with retry) states; mobile first. Keys only in .env (placeholder in .env.example).
- Tests for logic (money, statuses, timers, route maths). Run tests and the build before saying done. End with: files changed, how to test by hand, what's unfinished.
- Screens: one obvious primary action; primary button full width, bottom third, indigo, the only indigo element; advanced options hidden until needed; never two equal buttons side by side; delete/cancel smaller and away from the primary.
- Every tap responds instantly (pressed state, "Processing payment…"); skeletons instead of blank screens; confirm success; errors say how to fix the problem.
- Onboarding comes before sign-up (Duolingo style, `src/features/onboarding`); never pre-check marketing opt-ins or paid add-ons.
- Audit and prioritised fix list: docs/HAYVE_AUDIT.md.
- Holidays: `api/holidays.ts` (partner packages, post-trip rating, share code), screens `src/app/holidays/*`, public `/t/[code]`, trip card `src/features/holidays` (privacy zone around the hotel; never draw invented straight lines).
- Centre button: `src/features/nav/CentreButton.tsx` + `actions.ts` (primary action from onboarding `primary`; hold for the half-circle menu). Celebrations: `celebrate()` from `src/features/celebrate.tsx` for good moments.
- Admin import (demos): `src/features/admin/ImportPanel.tsx`, parser `importParse.ts`, backend `api/importer.ts`, server `/admin/import/fetch` (`server/src/pagefetch.ts`, public addresses only).
- Driver/courier ID check (demo): `/verify?role=driver|courier`, `business.verifyIdentity`; registration requires a verified ID.
- Growth plan: docs/GROWTH.md.
- Playbook (UX, onboarding, motion, words, money, maps lessons, ship checklist): docs/APP_PLAYBOOK.md. Follow it for every screen.
